# 三类实验共用的数据准备手册

本阶段从现有 MAWI、GRN PCAP 开始，不采集、不发送数据包、不运行检测器。产物供 Suricata 通用规则、Zeek＋监督模型、Zeek＋AE 共用。以下命令均在项目根目录运行。

## 1. 准备运行环境和目录

需要 Python 3.10 或以上。数据准备模块只使用标准库，不必先安装 Suricata、Zeek 或机器学习框架。项目安装会同时安装 Suricata 实验模块所需的 PyYAML。

```bash
python3 --version
python3 -m venv venv
source venv/bin/activate
python -m pip install -e .
mkdir -p data/raw/mawi data/raw/grn outputs
prepare-data --help
```

当前项目根目录已创建 `venv/` 并以可编辑模式安装本项目。首次部署时执行上面的完整命令；以后每次新开终端，进入项目根目录后执行 `source venv/bin/activate`，无需重复创建或安装，也无需设置 PYTHONPATH。可用 `python -c "import sys; print(sys.executable)"` 确认解释器位于本项目的 `venv/bin/python`。退出虚拟环境执行 `deactivate`。

如果首次创建提示缺少 ensurepip，在 Ubuntu 安装 `python3-venv` 后重新创建。虚拟环境不提交版本控制、不从其他操作系统复制。

原始文件放入 `data/raw/mawi/` 和 `data/raw/grn/`，保留原始文件及业务日志。工具不修改原文件。输出目录必须不存在，防止覆盖历史实验。

## 2. 确认输入与标签

- 输入必须是经典 PCAP，支持微秒／纳秒、大小端格式；不直接支持 PCAPNG。仅支持 Ethernet（含 VLAN）、RAW IP、Linux cooked v1/v2，同一轮输入链路类型必须一致。
- GRN 输入应只包含已确认的目标业务流量。SSH、系统更新等先根据真实业务记录离线筛除，另存派生 PCAP 并保留筛选依据。不能仅凭整机地址确定所有流量都是 GRN。
- 清单的 `target_only: true` 是人工确认，不是工具自动识别结果。如果不能确认，先不要生成正式标签。
- MAWI 在本实验中标为背景，含义为非目标数据来源，不代表全部正常。需要确认所选背景不存在已知目标 GRN。
- 相同会话跨多个文件时，先在原时间轴上整理为一个经典 PCAP，处理重复抓包，并保留来源记录。不要把同一会话的分段当独立采集。

第一版纳入可读基础传输头的、非分片 TCP/UDP 数据包。其他协议、IP 分片、IPv6 扩展头、损坏或过短的头部不会进入混合文件，排除数量见检查报告。截断载荷但头部可读的包可以纳入，字节量使用 IP 头声明的长度。此范围必须在报告中披露；若 GRN 依赖被排除的类型，应先扩展解析器，不能把这些包静默当作已完成评估。

## 3. 检查每个原始文件

示例文件名请替换成实际路径：

```bash
prepare-data inspect \
  data/raw/mawi/test.pcap data/raw/grn/test.pcap \
  --timeout 120 --output outputs/initial-inventory.json
```

输出记录 SHA256、包数、链路类型、捕获截断包数、各类排除包数、可用连接数和可用 IP 字节数。损坏的记录或倒退时间戳会报错，先定位原因，保留修复依据，再生成新派生文件。

这里的“连接”是规范化双向五元组＋120 秒空闲超时。两个方向归为同一条记录；间隔严格大于超时才开启新记录。这是统一的数据准备会话口径，并不保证 TCP 会话完整，也不保证与 Zeek／Suricata 的默认连接划分一致。TCP FIN/RST、新 SYN 不作为额外分界；跨观测边界的流不自动删除。报告应称“观测到的连接段”，后续需通过五元组＋时间范围映射检测器记录，处理一对多情况。

检查阶段也要人工确认：单向流比例、抓包边界、卸载影响、时间精度及两种来源载荷可比性。当前自动报告不计算这些全部质量指标。

## 4. 按独立日期／批次划分数据

```bash
cp configs/captures.example.json configs/captures.json
```

编辑 `configs/captures.json`，每份输入一个条目：

```json
{"path":"../data/raw/grn/test.pcap","class":"grn","group":"grn-run-20261001","split":"test","target_only":true}
```

字段含义：`path` 相对清单文件目录；`class` 为 `mawi` 或 `grn`；`split` 为 `train`、`validation`、`test`；`group` 为不可跨分区的日期／独立业务会话组。同一来源类型下相同 group 必须属于一个分区，相关日期和部署应按实际相关性合并成组。

由人工明确分组，不随机按包或连接拆分。多个日期和运行批次应覆盖各分区。30%／20%／50% 只是候选，最终由独立样本数、业务覆盖和模型学习曲线决定。可用多条清单项表示多个文件。

```bash
prepare-data validate configs/captures.json
```

工具检查字段、GRN 标签确认、组跨分区以及完全相同文件重复。它无法发现不同文件中重复的数据包／相同会话，也无法验证人工 group 是否真实独立；这需要业务记录核查。示例中的文件和日期组均为占位内容。

## 5. 固定背景并估算 GRN 需求

每轮固定清单中所选 split 的全部可用 MAWI 连接，各混合条件加入不同数量的完整 GRN 连接：

`GRN IP字节量 = 固定 MAWI IP字节量 × r / (1-r)`

比例参数使用小数：0.01% 对应 `0.0001`。例如固定 10 GB 可用背景时：

| GRN 占比 | 所需 GRN IP 字节量，约 |
|---|---:|
| 0.01% | 1.0001 MB |
| 0.1% | 10.010 MB |
| 1% | 101.010 MB |
| 5% | 526.316 MB |

这里采用十进制单位，以检查报告的 `eligible_ip_bytes` 计算，不使用 PCAP 文件大小。最高混合比例决定目标测试池的主要字节需求；最低比例仍需核查有效目标连接数量。若最低比例容纳不下足够独立目标连接，需扩大固定背景及目标池，不能只保证比例而忽略样本量。

固定背景指排除不支持报文后的全部可用背景，不指完整原始 PCAP 中的每个包。若希望减少背景量，先另存明确选定的背景输入并更新清单，混合程序不会按条件改变背景。

要做多轮实验，准备分别包含各轮独立测试批次的清单；训练、验证条目仍保留以供泄漏检查。不同轮明确记录共享背景或目标情况，不把复用当独立样本。

## 6. 先运行小规模预实验

GRN 测试池足够时，先生成 5%、纯背景和纯目标，检查全流程：

```bash
prepare-data mix configs/captures.json \
  --split test --ratios 0,0.05,1 --seed 2026 \
  --timeout 120 --tolerance 0.05 --output outputs/pilot01
```

工具按固定种子打乱 GRN 连接，选择最接近目标比例的非空完整连接前缀；比例升高时使用嵌套目标子集。0% 和所有小于 100% 的条件使用完全相同的全部可用背景包及其时间戳。100% 是独立纯 GRN 校验组，使用全部可用目标且不含背景，不属于固定背景混合条件。各条件不保证相同总字节量或观测时长。

完整连接抽样可能低于或高于目标 GRN 量，记录实际占比。`--tolerance 0.05` 表示相对比例误差最多 5%，不是允许偏差 5 个百分点。误差过大或 GRN 不足时，在写输出前报错；补充数据或明确调整预实验目标，不要删包凑数。

## 7. 构造正式条件

```bash
prepare-data mix configs/captures.json \
  --split test --ratios 0,0.0001,0.001,0.01,0.05,1 \
  --seed 2026 --timeout 120 --tolerance 0.05 \
  --output outputs/round01
```

如需其他误差容限，应预先规定并记录。工具要求目标池满足所有条件的 GRN 字节需求、且实际比例误差通过后才开始输出。运行中断可能留下不完整目录；保留用于排错，重跑时换新目录。

混合过程保持每个选中连接的全部可纳入包，不随机删包、不复制目标、不改变包长和载荷。每份源文件仅做一次整体时间平移，使其首个可用连接从固定公共时间点开始，再按纳秒时间戳排序。文件内部跨连接相对时间也保留，文件间时间关系是合成的。原始微秒时间戳写成纳秒格式不会增加真实精度。

跨源出现相同双向五元组时停止，防止平移后连接混并。第一版不自动改写地址和校验和。需要先制定单独可追溯的地址映射方案，再重新检查；不能通过忽略冲突完成正式实验。

## 8. 检查产物

```text
outputs/round01/
  inventory.json
  ratio_0/
    mixed.pcap
    labels.csv
    manifest.json
  ratio_0.0001/
    ...
  ratio_0.001/
  ratio_0.01/
  ratio_0.05/
  ratio_1/
```

- `inventory.json`：本轮输入路径、校验值、采集组、纳入／排除统计。
- `mixed.pcap`：实际交给三类实验的输入，保留源报文捕获内容和原始线长。
- `labels.csv`：一行一条观测连接段，包含标签（1=GRN，0=背景）、协议号、规范化端点、起止纳秒、包数、IP 字节量、来源组、源连接编号和时间平移量。端点 A/B 按排序定义，不代表发起／响应方向。
- `manifest.json`：目标／实际字节比例、实际包数和连接比例、分区、种子、超时、两类计数、输入清单和输出校验值。

标签只供匹配和评价，不作为检测器输入。人工抽查两方向包、时间映射与连接计数。可以再次检查输出：

```bash
prepare-data inspect \
  outputs/round01/ratio_0.01/mixed.pcap \
  --output outputs/round01-check.json
```

核对输出可用 IP 字节量等于清单两类 IP 字节数之和，包数与标签求和一致。不要要求重新解析的连接数机械等于标签行数：源文件内同一五元组的边界与后续检测器超时可能不同，必须核查映射歧义。

## 9. 训练／验证数据的交接

清单中的 train、validation PCAP 保留分区，不必为了训练强行生成全部低占比混合文件。下一阶段 Zeek 使用相同配置分别提取这些输入的连接特征，关联来源标签。监督模型用 GRN＋背景；AE 仅使用 MAWI 背景训练与校准。调参与阈值校准应在验证组内进一步分开，禁止使用测试数据调整。

正式运行 Suricata 前另做已知阳性样本校验。纯 GRN 只用于观察基础告警，不替代阳性校验。

## 10. 阶段验收与已知限制

验收要求：输入已核实标签、分区无已知会话泄漏、质量报告已审核、最低比例有足够独立目标样本、实际比例符合预设容限、输出计数及校验值一致、混合来源可追溯。没有真实输入时只能通过合成测试验证程序，不能宣称实验数据已就绪。

本版本按流元数据驻留内存，输出时还会把选中报文载入内存排序，且每个条件重复读取文件。适合小规模预实验，不适合直接处理最低占比可能产生的 TB 级数据。正式大规模运行前需要实现外部排序／流式合并和磁盘索引；当前应按独立批次控制单轮规模，不能通过复制少量流量扩容。

本阶段不会统一截断长度、匿名化 IP 或模拟 MAWI 漏包。连接特征应选双方可靠可见字段；Suricata 内容规则必须另行审核载荷适用性。MAWI 载荷缺失导致的低告警不能解释为 GRN 反探测成功。所有排除样本需要报告端到端覆盖率，不能仅在可处理子集上宣称整体低检出。

代码验证：

```bash
python -m unittest discover -s tests -v
```

准备完成后，继续 [Suricata 通用规则实验](suricata-generic.md)。

监督分类阶段需为 validation 数据按独立采集组声明 `role: tuning` 或 `role: calibration`，具体见 [监督分类实验手册](supervised-classification.md)。模板已包含两类角色；数据准备阶段仍只使用 split 构造对应混合条件。

第三类检测器的实现与命令见 [自编码器异常检测手册](autoencoder.md)，复用共用测试集及 Zeek 特征。

当前混合策略已改为固定背景，旧版本生成的文件保持原样。正式对照时请使用新输出目录重新生成，并重新提取测试特征、运行检测。不同占比的 GRN 数量和组成可能不同，应报告连接数／业务覆盖，并对共同目标子集作配对比较，不能将 TPR 变化全部归因于占比。

只有单份原始 PCAP 时，可先使用 [分组拆分工具](pcap-splitting.md)，输出训练、调参、校准和测试 PCAP。请保留原始来源信息并核查业务会话独立性。
